# 普通 E4 账本提交的具名事务预算

2026-10-24，维护者明确委托按 `seal-vs-budget-decision.json` 的较小方案实施；AI 代理执行，不替代153迁移的真实人工审阅。

本决定仅修订活动 v1.1 详细合同 §5.13 第1项及正式方案 §15.2中**普通 policy_v1 E4 提交**适用的内部事务上限：具名档位 `e4-native-ledger-commit` 为60秒。归档合同原文保留，不暗改共享7秒的含义。原7秒工作额度依据是200人考勤14条SQL／222ms；当前E4提交需在锁内执行完整来源、评价与账本校验。此前两审17.811／35.849秒已提交，正式账本提交仍在7000ms预算下于7563ms报P2028；这不是完整提交耗时测量，也不证明60秒充分。

60秒是待验证的工程资源上限，不是HTTP响应SLA，也不表示性能优化。最坏连接和事务锁占用窗口约为原来的8.6倍；竞争方仍可能在原4秒取锁限制下被拒绝。共享标准档位7秒、Human D7 V2/V3档位15秒、单次取锁4秒、10个全局锁槽及原准入数量不变。

只有顶层 `LedgerPostingService.commitBatch` 可从数据库读取的 `policy_v1`、`submitted`、`time_revision` 独立正式根选择60秒。Activity→Run→Version→Batch持锁后重新核对批次父键、自己的正式根及更正分类；根变化或普通／更正分类漂移失败封闭，不在事务中升级档位。旧批次的合法重放按自己的版本根复核，不因run后来推进版本而失效。客户端不提供预算。`commitBatchWithin`、conversion及D7既有外层事务所有者不改变。

完整E4／R4／原生约束、实时权限、成员锁、日状态基线与键集、重叠和日上限均保留；day-state、batch／run／result／segment、审计和outbox仍同一事务0%／100%发布。不增seal字段、表、迁移或新工作流；153有效修复保留，已撤回的selected154不恢复。

验收队列：静态／类型／lint／定向单测和独立复核 → 新隔离库真实8秒完整提交、61秒超限全表快照回滚、锁释放、同目标一次重试及重放不重复、分类漂移拒绝、默认与D7原档位 → 全部通过后一次原完整满额。任何FAIL／UNKNOWN停止并保留真实库及旧失败证据，不自动提高上限或重跑。

摘要读事务5秒不变；最终独立oracle的SQL30秒及全部双向差集／根摘要断言不变。后置PSet是历史137窗口优化器速度比较，单独报告为优化验收，不是业务响应SLA；现有执行和断言没有删除、放宽或预记PASS。满额尚未执行的部分仍为未验。

本决定不包含生产部署、扩大active500、人工3b代签、被拒绝的PR正文发布或其他受保护权限变更。首次空库上线无旧分／cycle历史续接转换需求。
