# 账本跨活动重叠查询的按键读取修复

## 目标及边界

修复 `LedgerPostingService.assertNoCrossActivitySegmentOverlap` 的计划不稳定问题。
2026-10-27 的 nightly 40501573528 中，8192 人用例的重叠查询客户端耗时
7729 ms，14 帧同一数据库 backend、同一 queryStart 的现场覆盖 7404 ms，均为
active、无所见 wait/blocker。三个 C3 失败也在该调用点触发 7 秒事务过期，但没有
各自对应的执行计划，不能断言四项根因均已证明。

原非执行计划包含 candidate 在前、existing 顺扫的连接形状；此前快运行按成员和
身份索引关联。普通 INNER JOIN 的书写顺序不保证执行顺序。两次运行的低统计读数
也不能单独解释差异。非执行 EXPLAIN 不证明实际 loops 或独占 CPU 耗时。

## 最小实现

仅把这条存在性查询改为当前活动身份 → 同 memberId 的身份 → 两侧 identity 键的
LATERAL 读取，复用同文件 `readDraftSegmentMemberIds` 的 `OFFSET 0` 边界。状态、
结果及签退条件放在各自身份键读取的边界外，避免拉平后先用全表状态过滤再连接。
该边界不强制索引，也不保证执行时间。

保留原四个表别名、`SELECT 1 AS conflict`、固定两个活动 ID 标量绑定、两个严格
相交不等式，以及所有冲突条件之后的唯一 `LIMIT 1`。不提前截断任何身份或段。
双方结果排除、状态、非空签退、跨活动条件及 SQL NULL 语义不变；原规则下零长度段
落在另一段内部仍会判冲突，此次没有修改这项行为。原成员锁内复核、错误传播、
7 秒事务、4 秒取锁、10 槽及审计/outbox 原子性保持。

## 验证与停止条件

改动前 29 项账本单测通过；补充空结果、冲突、原生错误、固定绑定及边界结构单测。
真实 PostgreSQL 测试用冻结原 SQL 对实际 service 调用做差分，逐案断言独立期望，
覆盖状态、结果、合法 NULL、区间端点/包含/零长度、活动/成员及多身份/多段。
各案 savepoint 隔离，最终回滚，并核对段行快照不变；保留原 AC-058 的真实提交拒绝。

队列为定向单测/轻检查 → 本文件对应真实 PG 语义测试 → 原 C3 文件一次 → 原 8192
完整用例一次。只有全过且必须检验历史连续上下文，才运行一次原顺序核心 42 链；
不跑全部 452 项。首个 FAIL/UNKNOWN 保留证据和测试库，诊断后再决定恢复，不重复求绿。
最终普通 CI、Smoke 和 Trusted 绑定新候选；旧 SHA 的绿色结果不替代它们。
