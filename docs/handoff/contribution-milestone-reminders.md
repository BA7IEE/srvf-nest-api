# 正式贡献入账的达标提醒（A9）

本能力接在既有正式账本提交协议中。代码与迁移文件不代表已合并、部署或启用生产闸门；存量提醒接续仍待单独决策。

## 用户能收到什么

- 沿既有申请选择规则，取本人最新、未删除且处于 `joining` 的申请，使用该轮年份截止日、门槛 5 和现有贡献计算核。不会另设入队资格。
- 只有正式账本使积分从 `<5` 变成 `>=5` 才登记。送审、审核通过、准备完成都不登记。
- 普通提交、自动提交及更正共用生效协议。更正读取冲回与重记后的净分，不按单条正分录判断。
- 同一申请/门槛只登记一次：4→5 登记；5→4 不撤回；再次 4→5 不重建意图。新申请独立，创建申请本身不触发积分跨线。
- 使用既有 `recruitment` 定向站内信和通知 worker。无新 API、DTO、队列或 cron；前端继续读本人通知 feed。前端适配、真实联调和外部渠道验收未包含在本次交付中。

## 为什么清理 outbox 后也不会重发

`TeamJoinContributionMilestone` 永久保存申请、门槛、轮次、前后积分、来源分录/批次及登记结果；按申请/门槛唯一，禁止改删和 truncate。它不依赖 outbox 保留，也不以 outbox 的有无推断是否提醒过。

所有前后计算都发生在现有人员锁之后。另按 id 锁申请行，与现有“申请→轮次”更新顺序一致，使截止年份在计算期间稳定。业务账本、跨线记录和通知意图使用同一调用方事务；审计、权限或后续步骤失败时整体回滚。重放已提交批次不重新登记。

已有永久记录需核对身份、门槛、版本、结果类型及语义 payload 校验值；不吞掉语义冲突。没有永久记录却已存在同 key outbox 时，即使内容相同也拒绝整笔提交，留待查明数据或混跑写入来源。

“通知意图登记一次”不是“外部渠道绝对投递一次”。worker 按原 lease/retry/dead 机制执行；暂态失败重试原意图，失去租约按既有恢复路径处理，dead 交现有处置流程，不能靠再次跨线创建替代意图。已经登记不代表已经送达、已读或第三方已确认。

## 历史未知申请

新代码仅在既有贡献读源为正式账本时，随**创建申请**写入不可变的 `contributionNoticeProtocol=1`；只读配置不另选来源或开关。已有申请及旧协议创建的申请保持 NULL；迁移没有默认填 1，也不扫描、回填或发送历史提醒。NULL 不能事后改成 1 来伪装新申请。

历史未知申请未来正式跨线时，积分照常入账，保存首个 `history_pending` 事实；没有 intentId，也不记为 `notice_registered`。后续跨线不会自动补发。这是待判定状态，不是“已提醒”或“永久不提醒”决定。

历史提醒收据如何核验、转换是否触发、未知申请如何继续提醒，仍需维护者批准。建议下一步采用独立、可审计的追加裁定记录，链接原待判定事实；确认历史已提醒或批准补发后，再决定是否登记意图，保留原证据。当前没有该裁定接口、批量补发或自动 backfill。旧账转换入口明确跳过本能力。

## 数据库变更与上线前提

候选迁移：`20261117190000_team_join_contribution_milestones`。

| 项目 | 影响 |
|---|---|
| schema / migration | 一个 nullable 申请协议列、一张永久事实表、两个父表复合唯一索引及同链 FK、CHECK、触发器 |
| seed / API / BizCode | 无新增；既有权限与审计事件不变 |
| 旧数据 | 旧申请保持 NULL；不生成历史事实/意图；原数据字段不改写 |
| DDL 锁 | ALTER 有短时排他锁；普通索引创建会阻塞对应父表写入，须由维护者安排部署窗口；保留 4 秒 lock_timeout |
| 兼容 | 旧代码可继续读原字段、创建 NULL 协议申请；启用新写入前须完成迁移、授权及既有全 fleet 切换要求 |
| 不可逆边界 | 新记录生效后不得删除去重事实或清空协议列；代码回退需保留新增结构与事实 |

表与触发器沿现有受信 NOLOGIN owner。Human 的 C 角色仅增加事实表 SELECT/INSERT、申请/轮次所需列的读取，以及不可变协议列的 UPDATE（PostgreSQL 的行锁需要至少一列 UPDATE 权限；触发器仍拒绝修改协议）。不授予申请状态、申请人或轮次修改权，不变更集群角色属性/成员关系。

INSERT 依据真实 `session_user` 拒绝 U 借 `SET ROLE C` 伪造事实；校验来源批次刚在同一事务提交、申请同链及新意图的完整信封。superuser 本就具有 schema 管理权；普通 U/P 仍必须遵循现有非特权登录资格，不能用 owner 连接代替 P。

生产普通运行角色 N 的确切名称与最小授权仍需维护者核对：新表需要 SELECT/INSERT，既有表需保持原读写权限；不提供 wildcard grant、不自动执行生产授权。回退时先沿既有维护只读流程停止写入，保留事实与协议列，再处理代码兼容；直接关闭 v1.1 会切回旧积分读源，不能称为无损回退。

## 验证与交付边界

常规验收覆盖精确门槛、零部分写入、真实审计后故障、复合锚拒绝、永久事实保护、重放、outbox 清理和投递重试。独立迁移验收覆盖空库回放、带旧申请升级、DDL 故障回滚、非法协议拒绝及角色属性/成员关系不变。

原生积分的双连接锁等待、重复跨线、新申请、Human V3 净分及真实 P/U 权限用例在既有 authenticated CI 文件中；须以该 CI 结果为准，不能用普通 owner 测试替代。具体通过/失败结果记录在 PR。

Human CI 保留原固定源码清单全部字段，仅从独立校验和锁定的候选迁移追加三个守卫函数定义。迁移验收将该源码预期与真实 PostgreSQL 定义比对；不以目标库内容生成预期，不跳过完整清单比对。生产 source-qualified 安装记录仍须按变更后的源码重新审查与生成，本候选不代替该操作。

A1/A2/A5/A8 仍延期；公开更正操作入口、前端页面、历史提醒接续均未因此完成。A3/A4 与退役分支合并时需核对读取审计是否重复、契约及生成物是否冲突；未经实际集成验证不能宣称旧分支剩余失败已消除。D5/D6/D7 容量诊断不属于本改动。
