# 服务主体与附件元数据授权收口

本变更基于 main `a4c7eeb313748d2c42c1c32357d40533f6e46cfe`，不改变部署或开关状态。

ServicePrincipal 的八个既有 System API 在 Service 层执行各自已声明的 GLOBAL RBAC 权限。匿名仍为 HTTP401／40100；没有所需权限为 HTTP403／30100。读接口同样使用当前调用者；请求、成功响应、权限码、角色绑定与原事务不变。创建凭证在生成任何 secret 之前完成授权。内部 token 换取后的 `markCredentialUsed` 不属于这些控制面入口，保持原有机器路径。

附件 `PATCH /api/admin/v1/attachments/{id}` 仍只用 update 权限决定能否编辑元数据。调用者没有该附件的独立 view 权限时，成功响应的 `accessUrl` 为 null，且不会执行下载链接解析；有 view 时保持原有解析和到期规则。客户端不得将元数据更新权限当作文件读取权限。元数据提交后仍可能因响应查询失败而报错；本候选没有新增业务回执或改变既有更新的重试语义。

隔离测试使用合成认证和内存数据库替身。合法的凭证创建用例在生成入口被哨兵截停，附件用例不会签真实 URL；不宣称完成真实凭证创建、真实数据库事务、外部存储或生产验证。授权清单、模块摘要及 OpenAPI／客户端派生物随代码同步；完整 CI 与生产资格是各自独立的验证边界。
