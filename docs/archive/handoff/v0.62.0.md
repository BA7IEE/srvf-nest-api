## 2. 本版交付

- **活动责任闭环**:正式队员可按组织范围发起；独立 reviewer 审核，发起人具备审核资格时可直接发布；owner、initiator、报名协办与考勤协办职责显式化并支持移交/收回，职责结束后下一请求即时失权。
- **发布与考勤**:published 变更走完整 proposal 审核后原子应用；考勤支持独立一审/终审、退回与重提，owner 声明完成后进入明确闭环状态和下一动作；取消活动显式派生 `cancelled` 闭环。
- **跨组织与离队**:跨组织发起须显式角色授权并锁后重验目标组织、账号和正式队员资格；离队影响预检阻止未处理的 draft initiator、active owner 与当前/未来报名义务断裂。
- **本地前端联调**:仅限 `development/test` 与 `app_local_frontend*` 的 17 账号幂等 bootstrap、只读验证、隔离聚合 E2E 和 A–I 手工联调说明就绪；不构成生产人员配置。
- **可见性与组织安全**:Decision 15.1=B / 15.2=B 落地；正式队员统一为 ACTIVE + `level-1..7`；department 覆盖 PRIMARY/SECONDARY/TEMPORARY/SUPPORT 有效任职；inactive 组织 RoleBinding 失效；ops-admin 当前任期与常驻 holder 约束线性化。
- **审计与附件**:audit log 读取按 SUPER_ADMIN / GLOBAL read 范围收敛；Content 根锁、双权限与 durable storage ledger 闭合附件生命周期；招新日志、证书不可变审计和通知日志移除敏感原文。
- **通知可靠性**:报名、活动、责任与考勤通知全部与业务状态/审计同事务写入 PostgreSQL durable outbox，worker 在事务外沿 retry/dead 语义派发；通知已读计数原子化，贡献达标按真实 capped before/after 且每 application+threshold 至多一次。
- **隐私与并发**:取消报名通知使用 `displayName（memberNo）` 或固定匿名标签；报名审核并发只锁定唯一 winner、最终状态、唯一审计与唯一通知，不依赖锁等待顺序。
