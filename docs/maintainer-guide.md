# 维护者手册 — 写给你(不写代码的那个人)

> 仓库里所有其它文档都是写给 AI 看的。**这一篇只写给你。**
>
> 你不需要看懂代码。你需要知道的是:**哪些时刻只有你能做决定**,以及那时怎么判断。
> 其余所有事,AI 会做,并且被机器守着不许乱做。

---

## 1. 这套东西的基本设计

AI 会犯错,这是前提,不是意外。所以这个仓库的做法不是「叮嘱 AI 别犯错」,而是:

**能做成机器检查的,绝不只写成文字要求。**

写在文档里的规则,AI 可能没读到、读到了没照做、或者读到了但那句话已经过时。
做成机器检查的规则,违反时会**当场被拦下**,并告诉 AI 正确做法。前者靠自觉,后者靠物理。

于是仓库分成两层:

| 层 | 谁保证 | 违反会怎样 |
|---|---|---|
| **机器执法层** | 脚本、hook、CI | 当场拦截 / CI 变红,合不进去 |
| **判断层** | AI 的自觉 + 你的拍板 | 没有自动拦截 —— 所以这一层被刻意压到最小 |

**你要关心的只有第二层**,而第二层里真正需要你出手的,是下面第 2 节那几件事。

---

## 2. 只有你能做的四件事

### 2.1 红区授权

有些文件改错了后果不可逆或影响全仓(规则入口、CI 配置、数据库结构、鉴权、执法层自身)。
这些叫**红区**。AI 写它们时会被 hook 当场拒绝,并请你拍板。

**AI 不能给自己发授权** —— 这是刻意的。自己给自己开通行证,这道闸就没有意义。

同意后,由**你**执行:

```bash
pnpm harness:grant '<路径>' --reason "<为什么>"
```

用完撤销:

```bash
pnpm harness:grant --clear
```

**怎么判断该不该批**:AI 必须先给你一段人话简报,说明「要改什么 / 为什么必须改 / 不改会怎样 / 改错了最坏什么后果」。
简报说不清楚 → 不批。**你听不懂就是它没说清楚,不是你的问题。**

授权只解开「能不能写」,**不解开「能不能合并」** —— 红区改动仍要你看过 PR 才合。

### 2.2 数据库不可逆命令

```
prisma migrate reset / migrate dev / db push
```

这三条被设成 **deny(直接禁止)** 而不是 ask(问一下)。区别在于:
**deny 表示任何事先授权都不算数,必须由你在那一刻亲自执行。**
它们会删数据,而删掉的数据没有回头路。

### 2.3 合并动了红区文档的 PR

AI 可以自己开 PR、自己跑 CI。但**改了规则入口(`AGENTS.md` 等)的 PR,要你看过再合**。
理由很简单:那是约束 AI 自己的东西,不该由 AI 单方面改完就生效。

### 2.4 发版

```bash
pnpm release:prepare <版本号>   # 改文件、写日志、生成交接快照(不提交、不打 tag)
pnpm release:finish  <版本号>   # 打 tag、发 GitHub Release(不改任何文件)
```

分两段是刻意的:第一段只动文件,你可以先看;第二段才对外发布,不可撤销。

## 3. 出事了怎么办

| 症状 | 多半是什么 | 怎么办 |
|---|---|---|
| AI 说「全绿」但你不放心 | 可能只跑了快检查 | 让它把**实际命令输出**贴出来。规矩是:所有判断必须给证据 |
| CI 红了,AI 说「跟我的改动无关」 | 有时是真的(偶发),有时不是 | 让它说明**红在哪一条检查、为什么与本次无关**。说不清就是有关 |
| AI 反复在同一个地方出错 | **这是 harness 的 bug,不是 AI 态度问题** | 让它把这条错误做成机器检查(加进守护 + 事故回放集),而不是「下次注意」 |
| AI 要你手动做一堆步骤 | 步骤应该是脚本 | 问它「这一串能不能做成一条命令」。要背的口诀迟早会背错 |
| 换了新会话,AI 好像忘了规矩 | 正常 —— 规矩在文件里,不在记忆里 | 不用重复叮嘱。恒读文档 + hook 会自动生效 |

## 4. 命令速查

只列你可能自己跑的。全部命令见 [`docs/ai-harness/README.md`](./ai-harness/README.md)(那页是给 AI 的)。

```bash
pnpm agent:preflight        # 开工体检:环境、是否落后主干、有无未合 PR
pnpm agent:check:quick      # 快检查:lint / 类型 / 单测 / 守护自测(热缓存约 25 秒,冷跑约 1.5 分钟)
pnpm agent:check:full       # 全量检查(含 e2e)—— 权威口径是 PR CI 冷跑,别在自己电脑上跑:本机连跑必出大批假失败(2026-08-02 拍板);日常用 agent:check:quick
```

```bash
pnpm harness:replay         # 回放历史事故:那些踩过的坑现在还会不会被拦住
pnpm harness:selftest       # 守护自检:守护本身有没有失效
```

`harness:replay` 值得解释一句:仓库把**真实发生过的事故**记在册子里,每条都能重新触发一次,
看守护还拦不拦得住。**改完 harness 前后各跑一次,就能回答「规则还管不管用」。**
册子里也如实记着**还没被守住的**几条 —— 不假装安全。

## 5. 你不必读的东西

- `AGENTS.md` / `docs/process.md` / `docs/reference/**` — 写给 AI 的规则,你不用背
- `docs/archive/**` — 历史归档,只代表当时的决定,**不是当前事实**
- `CODEMAP.md` / `RBAC_MAP.md` / `openapi.json` — 大部分是机器生成的
- 任何 `*.spec.ts` — 测试代码

真要了解现状,读一份就够:[`docs/current-state.md`](./current-state.md)。

---

## 6. 一个提醒

这套 harness 的价值不在于「AI 从此不犯错」,而在于**犯了错能当场被发现**。

所以当 AI 告诉你「某某检查拦住了我」时,那不是坏消息,那正是它在工作。
真正该警惕的是相反的情况:**一路顺畅、没有任何东西拦过它**。
