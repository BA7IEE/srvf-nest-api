# 工具陷阱清单 —— 会让你得出**错误结论**的读数

> **这份文档只收一类东西:不报错、退出码正常、读数看起来完全正常,而它测的根本不是你以为的那个量。**
>
> 不收「用法说明」,不收「最佳实践」。**每一条都是本仓实测栽过的**,附当日读数。
>
> ⚠️ 为什么单独成文:这些坑与工具链绑定、与本仓无关,**换一个 AI 来做同样会踩**。
> 规则在 [`AGENTS.md`](../../AGENTS.md),事实在 [`current-state.md`](../current-state.md);**本文是教训**。

## 0. 总判别式

> **读到「零」或「异常整齐」的读数时,先验仪器,再下结论。**

本仓 2026-08-25 一天内,总控在工具读数上错了 **13 次**,其中 4 次已把错误结论说出口。
**每一次的读数都不报错。**

具体做法:
- 按路径过滤读到 0 ⇒ 先 `ls` 验那个路径**存在**
- 计数读到 0 ⇒ 换**第二个工具**复核(`grep` → `node`/`python`)
- 读数「太整齐」(全 0 / 全命中 / 恰好全过)⇒ **那本身就是可疑信号**

## 1. `grep` 家族的「不报错的零」(五种)

### 1.1 `grep -E` 里写 `\|` 当「或」

```bash
grep -aciE "archivedAt|archiveWaiting" f    # ✅ 裸 |
grep -aciE "archivedAt\|archiveWaiting" f   # 🔴 \| 是字面竖线 ⇒ 静默 0
```
**实测**:四个查询全返回 0,看起来像「这些功能一个都没做」,实际 4 / 1 / 1 / 2。

### 1.2 `\s` 在 BSD `grep -E` 里不是空白

```bash
grep -acE "^\s+pnpm"      # 🔴 macOS 上恒 0
grep -acE "^[[:space:]]+pnpm"   # ✅
```
**实测**:据此差点断言「另一条 lane 报错了」,而对方是对的。

### 1.3 分组内锚点交替静默恒 0

macOS BSD `grep -E` 的 `(^|X)…` 形式**返回 0 而真值非 0**,不报错。
⇒ 判据脚本一律用 TS/node 的 lookbehind,别用 shell `grep`。

### 1.4 `-o` / `-h` 摘掉文件名 ⇒ 下游按文件名过滤**完全空转**

```bash
grep -rohE "prisma\.[a-z]+" src/x/*.ts | grep -v spec   # 🔴 -o 不输出文件名,后面这层滤了个寂寞
```
**实测**:据此断言「某文件直查考勤表」,而该文件 `prisma.` 命中 **0** —— 命中全来自同目录的 `.spec.ts`。
⭐ **判别式**:管道里要按文件名过滤,**上游就必须带文件名**。正解是先按文件迭代,或用 `--include`/`--exclude`。

### 1.5 大文件被静默当二进制跳过

本机 `grep` 对 **200KB+** 的 `.ts` 判成 binary ⇒ `-c` **不打印数字、退出码 1**。
本仓有多个这样的文件(`schema.prisma` 328KB · `biz-code.constant.ts` 164KB ·
`harness-guards.selftest.ts` 292KB)。
⇒ 🔴 **一律加 `-a`**。

## 2. `git` 的两种

### 2.1 `git diff -- <不存在的路径>` 静默返回 0

```bash
git diff A B --name-only -- docs/CODEMAP.md   # 🔴 该文件在仓库根,不在 docs/ ⇒ 恒 0
git diff A B --name-only -- CODEMAP.md        # ✅ 1
```
**实测**:据此告诉维护者「CODEMAP 一个字没改过」,实际该分支上 **6 个提交**动过它。
⚠️ 尤其危险的是**凭印象补目录前缀**:本仓 `CODEMAP.md` 在根、`ROUTE_AUTHZ.md` 在 `docs/ai-harness/`、
`process.md` 在 `docs/` —— **没有统一规律**。

### 2.2 `git log --all <ref>` 把被查对象自己也算进搜索面

```bash
git log --all --format='%s' main | grep -F "$subject"   # 🔴 --all 覆盖了 main,分支自己也在里面
git log --format='%s' main | grep -F "$subject"          # ✅
```
**实测**:七条提交全部显示「已在 main」——**每条找到了自己**。

⚠️ 顺带:本仓用 **squash 合并** ⇒ **按提交标题判「这条活儿进 main 了没」结构上不可靠**,
只有**内容**作数。

## 3. shell 层:管道吃掉退出码

```bash
cmd | tee log; echo $?     # 🔴 读的是 tee 的退出码
cmd > log; echo $?          # ✅
```
**实测**:据此把一个红判据读成 `EXIT=0`。
⭐ 与之同族:**判红绿一律看退出码,别数 `✓`/`✗`** —— 脚本崩溃时 `grep -c '^✗'` 返回 0,
与「全过」**同读数**。

## 4. 本仓工具:`harness:needs`

### 4.1 它**不认授权**

`pnpm harness:needs` 是**纯静态预算** —— 它回答「这些路径要哪些授权」,
**不读令牌、不反映当前授权状态** ⇒ 「请维护者执行」那段**恒会打印**。

🔴 **验授权在不在,只有一条路**:
```bash
cat "$(git rev-parse --git-path srvf-redzone-grant.json)"
```
⚠️ 路径必须用 `git rev-parse --git-path` 取(worktree 下不是 `.git/`)。

### 4.2 🔴 用**通配符**问会漏报,而且方向是「放行」

```
harness:needs 'docs/ai-harness/**'            → 0 个需要授权   ← 🔴 假的
harness:needs 'docs/ai-harness/ROUTE_AUTHZ.md' → 1 个需要授权   ← 真的
```
⇒ **一律逐文件查。** 漏报方向是放行 ⇒ 你会以为不用授权。

### 4.3 它只核**你点名的路径**

它对你**没想到的后果**结构性沉默。
⇒ 「用了机器查」这层保证是**虚假的安心** —— 喂进去的清单本身是猜的。

⭐ **改一列 schema 的真实后果面(实测,可直接复用)**:
```
prisma/**                                              # schema + migration 一条 glob
                                                       # ⚠️ 授 'prisma/schema.prisma' 不含 migrations(精确路径匹配)
harness/domain-map.json                                # 改列 ⇒ digest 陈旧
harness/state-machines.json                            # 同上,且无 --write 入口 ⇒ 只能手改
test/contract/__snapshots__/openapi.contract-spec.ts.snap
6 份 test/e2e/*-migration.e2e-spec.ts                   # CURRENT_MIGRATION_COUNT 手动 +1(非红区,但必改)
```

## 5. 生成物刷新:`docs:refresh` 是**动作**,不是**闸**

### 5.1 刷完之后再改任何东西,它就过期了

**实测两个读数**:加一个 e2e 文件 ⇒ `CODEMAP.md` 的 `e2e/` 行 **306→307**;
合入别人的 PR ⇒ **307→308**。

⭐ **纪律**:`docs:refresh` 必须跑在「**最后一次写操作**」之后,而 **`git merge` 也算写操作**。
⚠️ 而「先实现 → 刷 → 再补测试」**恰恰是最自然的顺序** —— 这个坑天然会踩。
⚠️ **刷完当场 `git add`**,别「判据绿了」就当完事。

### 5.2 它的覆盖面 = 它枚举生成物的**那个来源**的覆盖面

`scripts/refresh-generated-docs.ts` 的刷新集合**从 `package.json` 的 `docs:*:check` 脚本名现算**。
⇒ 在 `package.json` 里**没有脚本名**的判据(如 `check-frozen-drafts-ledger.ts`)
**整个在射程之外**,而它的自证对此**结构性失明**。

**实测**:同一分支跑过 `docs:refresh` **两趟**、两趟自证全过,
而 `FROZEN_DRAFTS.md` §2 读数块**全程陈旧**,最后由 CI 抓到。

⭐ **判别式**:问「它从哪儿数出这批生成物的?」——
**没被那个来源登记的,入口和它的自证同时看不见。**
⚠️ 别把这条读成「该判据无执行位」——它有(CI 的 `redzone-scan` 直接调它),
**失明的是刷新入口的自证**。

## 6. 测试与判据:三种「看着在守、实际没守」

### 6.1 断言塞在一个 `it` 里 ⇒ 后面的**从未被执行**

jest 在一个 `it` 内**首个失败即停**。
**实测**:7 格断言塞在一个 `it` 里,做变异对拍时第一条(正向)先红
⇒ **三条反向断言一条都没跑到** ⇒ 「判据有判别力」**结构上观测不到**。
🔴 而这在**基线全绿时完全看不出来**。

⭐ **凡是要靠「红集精确」证明判别力的判据,被测的每一维必须各自成 `it`。**

### 6.2 恒定返回固定行的 mock ⇒ 把「查询被收窄」整类变异藏住

**实测**:变异「子树查询改成只取直属」,第一版 mock 下只红 **1 例**且红在结构断言上、
**行为侧一例没红**;把 mock 改成「真施加 `where` 条件」后同一变异红 **3 例**。

⭐ **正解**:列表/查询类断言打在**交给 ORM 的 `where`**(或写路径的 `data`)上,不是返回值上。

### 6.3 豁免名单 / 白名单静默腐烂

**实测**:`C1_EXEMPT` 指着一个已被删除的文件 ⇒ `includes()` 永远不匹配
⇒ **不生效、不报错、不改判定、没有任何机器发现它烂了**。

⭐ **正解**:名单里每一条都要有**自证** —— 「它指的东西必须真的存在」/「必须真的已消失」。
⚠️ 加白名单时**别只加名单**,同时加自证;否则就是「装了个没验过的报警器」。

## 7. 变异对拍本身的三个坑

1. **仪器要真的会执行被测代码。**
   实测:用 `tsx` 直跑一个判据脚本做对拍,变异前后**恒退 0** ——
   真因是该文件是**纯库、无 CLI 入口**,直跑什么也不做。换成真执行位才拿到 0 → 3。
2. **粗变异会让别的断言先抛。**
   实测:做「锁后复判」的对拍时,若直接删掉 `FOR UPDATE`,**屏障断言会先红**,
   「判决翻转」那一行根本走不到 ⇒ 读数只能证明「锁没了屏障会红」。
   ⭐ 正解:**只否定被测的那一维**(锁照取,单把决定性计数换成锁前快照)。
3. **红集「一改就全红」= 判据没隔离开维度**;**红集精确且两两不相交**才是有判别力。
   ⚠️ 变异若**一条都不红**,如实说「这条判据没有判别力」,别改断言去凑一个红。

## 8. 前置条件:分母可能恒为 0

读到「等**稳定运行一段时间** / 等**没人报告**异常 / 等确认**旧 server 全关** /
等**存量数据**被逐条认领」这类条件时:

> 🔴 **先问一句:这个条件的分母在我们这儿存在吗?**

本仓从未上线、无生产库、无真实用户、无存量数据
⇒ 上述条件**结构上永远到不了**,既不可能满足也不可能证伪。

⭐ **正解不是「破例」,是换一个此刻就能判的等价条件。**
实测范例(DROP 两个遗留列):
```
E1 无新值注入   创建口 data 无该键;唯二 update 是回声写;可写 DTO 零该字段且有结构判据把关
E2 无语义读     对外出参一律来自新列;旧列的值没有任何一处进 API
E3 存量为零     当日复测 97 个可测库,非空计数全 0
                ⭐ 仪器自证:同表 count("title") = 行数 ⇒ 计数器看得见非空值
                ⚠️ 先验分母:99 库里有 2 个连不上(脚本原本静默跳过)
```
⇒ 三条全是**代码事实与当日读数**,不含任何时间量。

⚠️ **但别一刀切**:有些「等」是真的在等**一个人做决定**,那要**翻译成常识问题去问**,不是推翻。
判别:条件在等**一个外部事实发生**,还是等**一个人拍板**?

## 9. 判「一列还有没有人用」——别用字符串

只有四条通路能真正读写一列:

| 通路 | 形状 | emit |
|---|---|---|
| a | `prisma.<model>.*({ select / include })` | `SELECT` |
| b | `prisma.<model>.{create,update,upsert,*Many}({ data })` | `INSERT` / `UPDATE SET` |
| c | 已 select 出的行的属性访问 | 无(a 的下游) |
| d | `$queryRaw` / `$executeRaw` 裸列名 | 直接 SQL |

**不算数**:DTO 类字段(`@ApiProperty()`)· 局部变量 · 注释 · Swagger `description`。

**实测**:`grep coverImageUrl` 得 **69** 命中,看着像「到处在用」;
按上表判,真触点是 a×9 块 / b×3 处 / c×5 处 / d×0。

⚠️ 顺带:**「我知道这条 grep 不可靠」不等于「我知道它为什么不可靠」** ——
后者才决定换什么判法。当时我把原因说成「另一个模型有同名列」,实测那个模型**根本没这列**。

## 10. 类型系统作为执行位:有洞

DROP 一列后 `prisma generate` 会把它从生成类型里删掉 ⇒ 所有触点**编译不过**
⇒ `typecheck` 就是「漏没漏改」的判据。

🔴 **但有两类写法能绕开**(实测,变异后 `typecheck` 退 0 不红):
- 手搓 `Record<string, unknown>` 做字段对照表(两侧都不碰生成类型)
- 测试夹具的行类型手写

**实测后果**:其中一处若留着,`before['coverImageUrl']` 恒 `undefined`、快照侧恒 `null`
⇒ **每次变更审核都把这两键误报进 audit `changedFields`**。

🔴 **零 `as any` / 零 `@ts-expect-error` / 零类型断言绕过** —— 那等于把执行位拆掉。

## 11. 环境:红区授权令牌**按 worktree 存**

令牌落在 `$(git rev-parse --git-path srvf-redzone-grant.json)`,
**每棵 worktree 各有各的** ⇒ 在主仓发的授权,worktree 里读不到(反之亦然)。
⚠️ 而且 `harness:grant` **只认第一个路径** —— 多路径并排会**静默只授第一个且退 0**。

⚠️ CI 的**红区环境审批绑 SHA** ⇒ 之后推任何 commit(哪怕只是刷生成物)都会把它打回 pending。
⭐ **它必须是合入前的最后一个动作。**
