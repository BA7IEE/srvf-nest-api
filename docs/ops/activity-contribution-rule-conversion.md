# E2 旧贡献规则转换：第一层隔离能力

当前仅有 `app_test_*_w98` 隔离夹具能力。真实目录中的 31 个活动类型全部保持 `hold`；没有获批的类型→时长分类、角色、默认结果和生效时间映射。仓库里不存在获授权的真实存量转换入口，生产状态仍为 NO-GO。

## 可执行边界

- 新增的 `ContributionRuleConversionReceipt` 永久保留来源指纹、映射／批次摘要、目标 draft 版本锚和必要的旧字段快照；不复制备注、姓名或完整请求。旧 `ContributionRule` 不修改、不删除、不重算。
- 内部服务只接受 `e2_fixture_*` 虚构类型及政策 code，并在事务内确认实际数据库名为本类 `app_test_*_w98`。CLI 额外执行测试 URL 与连接双重校验。真实目录类型即使有旧规则也会拒绝。
- 默认 `dry-run` 零写入；`--commit` 必须传前一次 dry-run 得到的来源摘要。锁后重读来源与当前操作者 GLOBAL `contribution-policy.manage.version` 权限，再同事务创建 draft、逐源不可变收据和一条脱敏审计。相同输入重放返回原版本，不再写审计；冲突、指纹变化或权限失效回滚。
- 不启用选择、发布、结算、E3 shadow 或 Gate。测试结果只能证明固定夹具的转换能力，不是业务等价或真实数据已转换的证明。

## 隔离库操作

仅在维护者已批准本工作树的 `w98` 测试库、3b SQL 重签且本地连接守卫通过后，运行专用 E2E。用现有 Jest unit 配置指定 E2E 文件，可跳过通用 global setup，避免碰模板库或其他 worker；专用用例自行重建并回收 `w98`。`prisma migrate dev|reset` 与 `db push` 始终禁止自动执行。

CLI 仅用于测试夹具，使用 `pnpm exec tsx scripts/activity-contribution-rule-conversion.ts --help` 查看参数。操作者必须是隔离库内显式获 GLOBAL 管理权限的测试用户；真实数据库、真实类型或缺失签字映射都不允许绕过。CLI 不会建立夹具用户或旧规则，须由受控测试先准备。

如果隔离验证失败，停止提交，保留旧表和既有正式计算路径；修正候选代码后重新计算 SQL 摘要并再走 3b。已经形成的不可变收据不做物理回滚；未来真实数据修正必须另行评审并审计。本阶段不设计生产回滚脚本，因为从未授权生产执行。
