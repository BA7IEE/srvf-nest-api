# 成员建档与关联账号判权的部署预检

在应用流量切入前，用目标数据库连接执行以下只读预检。runtime_role 填应用实际连接角色。退出非零时检查部署角色契约及业务启用范围，再由维护者审核修正。该命令仅核验已验证的必要列权限；更宽的历史权限需另行对照部署 ACL 基线。

    psql -X -v ON_ERROR_STOP=1 -v runtime_role=实际运行角色 -f docs/ops/runtime-acl/check-member.sql

候选库曾在建档、绑定行锁、普通角色判权上分别缺少 Member 列权限及两张组织关系表的读取权限。数据库角色代表共用连接身份，应用角色由每请求的 RBAC/资源范围判定。预检不写 ACL，也不分配应用权限。正式环境应使用相应环境的角色与启用功能重新验证。保留授予来源和变更前列 ACL，撤销仅覆盖本次新增。

跨活动创建、报名、考勤、结算与通知的静态调用并非单一运行角色的授权清单。尤其后台处理者、受控数据库写入器和人工作业须按真实入口及部署身份拆分验证。不得按模块名或缺口数量批量赋权。
