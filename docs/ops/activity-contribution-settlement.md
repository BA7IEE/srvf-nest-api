## 1. 配置与制度

配置归 `src/config/app.config.ts` 的 `contributionSettlementMode`，环境变量为 `ACTIVITY_E4_CONTRIBUTION_SETTLEMENT_MODE`。

| 输入                                                    | 行为与边界                                             |
| ------------------------------------------------------- | ------------------------------------------------------ |
| 未设置或严格 `off`                                      | 配置合法，默认关闭；新普通结算仍用原制度               |
| 严格 `fixture` 且 `APP_ENV=test`                        | 仅在维护者批准的隔离测试进程使用，不代表实际环境已启用 |
| `fixture` 且 development／smoke／production             | 启动拒绝，不允许将真实服务改成 test 绕过               |
| 空值、空白、大小写／首尾空格变体、`active`／`shadow` 等 | 启动拒绝，不能把非法值默认成 off                       |

新版本固定 `legacy` 或 `policy_v1`，不根据后续环境重新解释历史版本。off 不删除已有原生证据；已有证明读取和合法幂等回执保留，新原生写入仍拒绝。历史 legacy 及其更正保持原制度，不转换旧 ContributionRule、不补写原生证明、不重算旧积分。

本配置不继承 E3 shadow、B6 控制面模式或 v1.1 Gate，也不自动开启它们。E5 正式启用、D8-OPS、真实映射登记、前端发布和生产操作各有独立前置，本轮均未执行。

## 2. 证明如何读取和解释

只沿既有 Human App managed 和 Admin 审核读面读取指定版本，使用原权限和当前资格复核；不会因为有证明、SUPER_ADMIN、前端按钮或测试模式而取得写入权限。调用面见[小程序交接](../handoff/miniapp.md#e4-负责人工作台贡献证明本地实施候选未提交未合并未部署)和[Admin 交接](../handoff/admin-web.md#e4-原生贡献证明本地实施候选未提交未合并未部署)，字段以生成的 OpenAPI/client 为准。

- legacy 省略 `contributionProof`，不能把它当作缺失原生证据，更不能重解释旧积分。
- native 的 `pending=true` 或空认定总分表示未准备／来源陈旧，不得显示为 0、按旧规则兜底或视作正式入账。
- 明确零分须有有效政策版本、来源和解释的完整证据；未配置政策继续阻塞，不新增 `not_required` 选择。
- 贡献积分与志愿服务小时独立；训练可有贡献但志愿小时为零，志愿服务有时长也可因明确零分政策为零。不能互相换算。
- `evaluations` 最多 100 项，只是解释预览；`hasMore=true` 时不能用预览求和代替根的总分／总数，也不能当作全量导出。
- 不从较新版本借证明覆盖历史。已准备、已提交、已审核和 committed 账本分别判断，证明存在不代表已经入账。

## 3. 失败取证与数据保留

业务预算保持原五秒／七秒／三十秒及查询上限。预算失败或完整性错误先停下收束证据，不能加超时、缩容量、关守卫、拆事务、减少权限复核或凭单次绿宣布根因关闭。

诊断只在具名、已授权的隔离库和写集内执行；本工作树目标为 `app_test_srvf_nest_api_delivery_flow_pilot_f59fbc_w98`。测试 fixture、受控清理及数据库生命周期须按本轮明确授权和租约规则运行，不触达模板、其他 worker、真实业务或生产，不使用 FORCE 或主动终止连接。本文不授予额外执行次数。

取证前校准字段和实际物理名：时间根没有 `operationKey`；通过 `ActivitySettlementTimeCommandReceipt` 的 actor／operation／key、`timeRevisionId` 和 `requestHash` 关联同活动证据。AuditLog 模型映射物理表 `audit_logs`，裸 SQL 不能照抄模型名。空目标查询通过不证明满额业务已通过。

错误后需区分客户端返回和独立连接看到的数据库最终状态，记录根、明细、命令收据及同链审计是否齐备；不能用单个根计数直接认定半提交。只保留固定阶段、计数、白名单错误、耗时和脱敏计划节点，不输出原业务 JSON、SQL 参数、身份、凭证或连接。

业务证据是保留资产：不得删除贡献证明、修改不可变评价、回滚已入账业务或重算历史以消除错误。未来如需恢复 off，只阻止新原生写，不能当作删除／降级旧证据的许可；可读取已产生原生证据的兼容版本才可进入未来恢复评审，不执行 migration down。
