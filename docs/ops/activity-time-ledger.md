# 分类时长账本操作说明（D6，实施验收中）

## D7-1 增量：仅更正认定，不改来源事实（分支验收中）

V2 更正须提供明确基础版本、基础账本摘要、非空原因和完整根分录认定快照，最多8000条。
服务段必须为空，不修改原分类桶或政策，不以新数值暗改旧贡献积分；旧结果如需改变必须单独显式填写。
首次逐条冲回根分录，此后冲回直接前驱的补记，再完整补记当前认定，零值也保留两条。原因永久保存。
分类与旧贡献账本只使用同一个更正批次和原子事务，worker不得自动提交更正，不能直接调用共享入账入口绕过。

查询使用 `versions/{settlementVersionId}/correction-ledger`，返回清单、根与前驱标识、内容摘要、四类汇总和稳定分页。
只有 committed 且收据一致时可见；汇总为十进制字符串，原因不在返回字段。历史查询仍实时核验根版本资格。
20229保留原错误码和消息，用于不支持的分类更正形状及自动提交旁路；不是允许客户端回退到V1的提示。
三张更正表永久追加；失败准备保留，不删除业务数据。以下 D6 说明保留其原适用范围。

本说明对应 D6 方案 A。当前代码尚未完成全部验收、提交或部署，不是生产执行授权。活动工作流 Gate 维持原状态；不得根据本文件开启 Gate、执行生产 migration 或修改真实业务数据。

## 账本含义

分类账本记录已提交分类修订中的认定秒数，包含志愿服务、培训、组织及不计入四类；零秒分录保留。全部分类相加不是志愿服务时长，更不是贡献积分。既有贡献账本、legacy 转换和 serviceHours 读源不因 D6 自动切换。

每个准备批次绑定一个不可变清单。清单和分录固定关联原批次、结算版本及分类修订，不能改为“当前最新版本”。重复准备或提交必须复用原批次；同一幂等标识但内容不同必须报错，不能覆盖旧内容。

## 读取

Human App 使用：

```text
GET /api/app/v1/my/managed-activities/{activityId}/time-settlement/revisions/{timeRevisionId}/ledger?page=1&pageSize=20
```

- pageSize 最大100，按参与身份、分类、分录ID稳定排序。
- 仅 committed 批次可见；准备完成不等于正式入账，ready 阶段仍不可读取正式账本。
- 调用者须满足当前 App 准入、显式分类结算读取权限、活动组织资格，以及负责人或该历史版本审核资格。管理员称号不替代这些条件。
- 汇总秒数是精确十进制字符串，客户端不得先转成32位整数；明细秒数为非负整数。四类汇总始终返回，零值不省略。
- 404 不应被客户端解释为“人数为零”或“自动重新提交”，它也可能表示引用不可访问。

## 准备、提交与重试

使用既有账本准备任务及统一提交入口，不新增独立队列或人工直写入口。准备分块完成后仍须核对完整来源集合与内容，才能进入 ready。

自动提交解析原终审人并重新校验其当前资格；用户停用、成员失效、撤权不能通过旧请求或重放绕过。等待成员等锁之后再次检查，不能拿等待前的授权结果直接生效。

提交、旧账本日汇总、结果状态及最后审计在同一事务内。自动提交失败退回同一任务等待既有重试安排，不能人工复制批次、重算基线或改分录来“解卡”。租约过期由既有 worker 接管；旧代际必须停止写入。

## 错误排查边界

| 业务码 | 含义 | 处理边界 |
| --- | --- | --- |
| 20226 | 来源不完整或不一致 | 保留批次及来源，定位同链关系；不补造分录 |
| 20227 | 幂等内容冲突 | 核对请求与原清单，不能覆盖或删后重建 |
| 20228 | 分录尚未准备完整 | 检查原任务及分块状态，沿原任务恢复 |
| 20229 | 分类账本更正尚未开放 | D7 前拒绝，不绕行 legacy 更正入口 |
| 20230 | 正式账本不存在或不可访问 | 核对明确版本、批次状态及当前资格，勿泄露不可访问内容 |

故障材料只收批次/任务标识、错误码、租约代际及脱敏时间线，不导出成员敏感信息、凭据或完整签名URL。调查先只读；新的业务数据修复方案必须另行评审授权。

## 不允许的操作

本文件不提供清库、补写或强制重放命令。最终上线须完成计划验收、最终 migration 签字、可信审批及独立部署授权。
