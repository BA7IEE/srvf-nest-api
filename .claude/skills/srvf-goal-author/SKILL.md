# srvf-goal-author — 把工作固化为可自驱的 goal 文本

[定位]
本仓协作模式(process §7.1):**goal 文本 = 维护者立项 + 拍板 + 授权记录**,runner 会话无人值守自驱,终版报告回传主会话元核验。本 skill 管起草侧:只准备文本不替用户下发;仓库一切变更由 runner 走 PR(分支保护强制)。并行 lane 语境(process §8):goal 同为 lane 的进程镜像,总控(`srvf-lane-orchestrator`)按写集声明排班,涉 schema 须随 goal 授予 migration token。用户是非职业开发者:决策问题用人话问、每题给推荐;工程细节自行代决并在 goal 里写明。

[第一性原则]

1. **必要决策前置**:复用本会话已明确的决定与授权,不重新询问同一事项。工程细节先查代码自行确定;仅对不能核实、且会改变业务口径、风险或授权范围的问题请求维护者拍板,给出推荐及依据。有依赖的问题先解决前置条件,独立问题可集中说明。未决项不得伪装为已授权 Goal;用户只要分析或文档时不推定实施授权。
2. **完整送审**:写前核实 live Git / GitHub 的 HEAD / 版本 / open PR、CHANGELOG `Unreleased`、`current-state §1` 和相关引用链。首次请求实施拍板前,同一份材料备齐方案、DoD、逐文件候选写集(含生成物、台账和测试后果面)、`harness:needs` 预算与验证方式。工程路径不让用户猜;不能确定的写集先侦察补齐。未来执行基点变化须重新核实,新增范围另行上报。
3. **目标导向,不教过程**:goal 写"什么必须为真"(DoD)与"什么不许碰"(边界),不写操作步骤——执行打法交给 runner:一条路不通换方法,穷尽多种尝试才停。流程纪律引用 process 节号(§7.1 循环 / §5.4 合并 / §4.1 人话简报 / §3 档位),不复述全文;规则与已知怪癖在仓库文档和项目 memory 里,runner 自取。
4. **DoD 可自证**:每条终态可用命令/产出物/计数在报告里自证;任务带探针(已完成判据),中断后同一 goal 文本重跑幂等续命。
5. **边界要硬**:只写真实约束(红区具体哪几处及 #294 授权范式、明确不做清单、档位切分、"偏离 → 人话简报停");放之四海的空话不写。
6. **内容齐全,材料合并**:背景简述已拍板事实与日期;Goal 必须含 process §7.1 五要素——DoD、探针驱动任务队列、授权清单、禁止域和精确写集。任务队列可很短,但每项必须能判断是否已完成。已有冻结稿引用即可,不重复抄写;按 process §7.2 准备同一阶段的完整送审材料,不另起只补工程清单的往返。不要为凑格式增加报告或独立台账。

### 常用范式(点名复用,不复述)

D 档沿既有冻结合同与获批阶段执行,完整方案/写集/验证方式在首次送审时备齐;能力与交接更新随对应实现 PR,机器可查的合并状态见 GitHub。不得因合并送审材料而合并获批的业务阶段或推定后续权限。E 档收口沿 srvf-release-closeout 两阶段,多件打包边界以维护者批准的 Goal 为准。

[交付]
goal 整段放代码块,附"复制给 goal 会话运行";给主会话留 2-4 条"跑完回传核验点"(终版报告贴回后据此元核验);含红区/不可逆授权的,提醒用户发送前扫一眼授权段。

[工作流程]
理解目标 → 侦察并备齐完整材料 → 集中解决必要的未决业务/风险事项 → 起草 → 交付 + 核验点。已获批的决定不重复确认。

送审前逐项完成 `docs/process.md §7.2` 的任务包核查:公开调用出口、历史迁移与当前服务兼容、夹具清理、所有受影响生成物、changelog 与交接均列入精确候选写集。验证命令须核实模板/worker/专用库及建库、迁移、清理副作用;`test:contract` 不视作无数据库检查,不把 w98 授权套给标准入口。保留独立迁移期望值与历史断言。

授权段按 process §7.2 默认建议一次覆盖实现、补测、范围内取证/修复、文档与提交推送同一 PR,列明可复用的测试库/worker 生命周期和必须后置的签字/令牌;不能默认推荐“验证后呈报、不提交推送”造成下一次等待。建议不等于授权,用户明确仅诊断/不推送时原样保留,不扩张现有任务权限。已有完整授权不重复请求提交推送;Ready、合并和生产仍核对实际获准终点。

探针队列把历史 schema/当前客户端、清理与 worker、满额性能风险放在大范围实现之前。CI 独有失败安排失败上下文的脱敏取证,本地通过不代替 CI;同一失败两轮未解按 §7.1 熔断报告并提出新的取证方法,不重置修复轮数。按 §7.2 复用输入未变的验证证据,在下一个业务目标的现有 PR 验证节检查是否减少等待,不另造流程台账。

实际越界按 §4.1 集中上报;同一等待请求只在条件变化时更新。使用本机技能副本前核对是否与已合入版本一致,不得把未合入草案当现行规则。
